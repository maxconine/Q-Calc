# QA and polish backlog (overnight run, 2026-11-20 01:30 → 09:30 PST)

Up to five agents run at once; new ones start every 30 minutes as slots free. Each takes the next `[ ]` item, marks it `[~] (agent N, HH:MM)`, and when done
marks it `[x]` with a one-line result. Go through items in order.

## Rules for every agent

- Goal for your item: find and fix bugs, speed it up, and make it feel like a first-party Apple app (native
  controls and keys, HIG spacing, smooth animation, VoiceOver, light/dark, no lag). Never drop or redesign an
  existing feature; parity rules are in `mac/PARITY.md`. Add improvements, don't take away.
- Read only what you need. Docs: `mac/README.md` (build, `scripts/drive.sh` to drive and `snap:` the dev build),
  `ARCHITECTURE.md`, `PERFORMANCE.md`, `mac/PARITY.md`.
- Tests: add a regression test for each bug fixed (core: `core/tests/*.rs`). Run `cargo test -p qcalc-core` (or the
  one test file) and, for Swift changes, `zsh mac/build.sh --arch=arm64 --skip-rust` (add `--run` only if you
  need to drive it). Another agent may be building at the same time: if a build lock waits, wait; never kill
  another process or delete `target/` or `.build/`.
- To wait for another build use `pgrep -f "^zsh native/mac/build"`, not `pgrep -f mac/build.sh` (it matches shells and
  wait loops block each other).
- Name scratch scripts and test-copy folders with your item number (e.g. `launch-86.sh`); never run another agent's.
- Stay in your item's files. Another agent works in the same checkout; don't touch its files, don't `git stash`,
  `reset`, `checkout` or switch branch.
- Never run `cargo fmt` on a whole package (only `rustfmt <your files>`), and never `git checkout`/`restore` a file:
  other agents have uncommitted edits in the same files.
- Never stage in the shared git index (others' plain `git commit` sweeps it up). Commit through a private index:
  `export GIT_INDEX_FILE=$(mktemp -u); git read-tree HEAD; git add <paths>` (or `git apply --cached` your hunks),
  `git commit -m …`, then `unset GIT_INDEX_FILE; git reset -q -- <paths>` — never a plain `git commit` without it. Shell variables don't survive between tool calls, so do the whole sequence in ONE command.
- Commit only your own files (`git add <paths>`, never `-A`) on branch `native` with a short message; never push.
- Record each Mac/core change in `windows/MAC_CHANGES_TO_PORT.md` (see `windows/PORT_RUNBOOK.md`); if a sheet
  changes, edit `scripts/gen_native_sheets.py`, never the JSON.
- The user said: use your best judgement on improvements. Make the call yourself and do it if it fits in your
  time; only list under "For the user" what is too big for one session or would remove/redesign something.
- Finish in under ~25 minutes. Report in 5 lines or fewer: what you tested, bugs fixed, improvements, what's left.
