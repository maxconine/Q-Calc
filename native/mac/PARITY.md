# Parity: native app vs the current app

Every row of `native/MAC_UI_PLAN.md`, checked against the native dev build. Pictures of the same input in both apps,
light and dark, are in `parity-screenshots/<scenario>-<theme>-{current,native}.png` (`parity/run.sh`): `live`, `dual`,
`history`, `select`, `graph`, `banner`, `games`, `help`. The "current" pictures are the web-view app's own page
(`dist/quick.html` with its boot flags, `parity/WebReference.swift`), so they are pixel-true to what users see.

Status: **✅ verified** in the native build (driven by `scripts/drive.sh` and pictured, or read back from the app's
view tree), **🟡 ported** (the code is there and builds, not exercised end to end here), **⏳ waits** on an engine
package (the native side is wired and lights up when it lands), **❌ missing** (not built yet; listed, not dropped).

All look values come from `src/index.css` (`Sources/Bar/Theme.swift`): `--bg` at 90% with the tape at 90% `--bg-tape`
(no blur, as today), 12 pt corners, 72 pt composer with 8 × 16 padding, 24 pt input and answer at −0.021 em, 20 pt
dual halves around a 17 pt ≈, 36 pt tape rows (13 pt muted expression, 17 pt answer at −0.015 em, 5 visible),
edge tools 11 pt medium shown on hover, accent green `#1d7a4c` / `#63d392`, ink caret.

## Where the logic runs

Every rule above is the TS's own, ported to the Rust core and answered through `Engine` (typed calls) or
`Engine.callJson` (`AppLogic.call`, module and name as in `src/lib`). Nothing runs as script: JavaScriptCore and the
`applogic.js` bundle are gone. `blankReason` and `missingUnit` take their `ok` callback inside the engine
(`Engine.blankSpan`, `Engine.missingUnit`, each piece read by `live` with the line's context); `lib/tour`,
`lib/analytics` and the constants the bar reads are in the core's dispatch. The host keeps only what is the
platform's: the install id's random bytes and the clock's zone offset for `localDay`.

The only web code in the app is the games bundle (`games.html`, built alone by `games.vite.config.ts`), loaded in a
web view only while ember & frost, trails or an effect is up; the other six games are native (section 10). The bundle
goes once those are ported too.

**Connect 4 board (native only):** Core Animation layers (`C4Layers`): the frame and holes are one shape each, each disc a layer, the fall (260 ms) and the held disc's slide (90 ms) are Core Animation's. A full-screen game with 40 held-disc moves and 3 drops took 0.08–0.09 s of app CPU against 1.47–1.52 s for the CPU-drawn bitmap; memory is the same (≈33 MB). Its big window is 460 wide in the card's units (`GameShellModel.bigWidth`), not the bar's 680, and the board shrinks to fit a short big window instead of being cut off.

**No fades (native only):** everything appears and changes at once. The bar shows at full opacity after one layout pass (the 0.1 s fade-in is gone); the rotating example, "✓ copied", a changed answer, hover highlights, the edge tools, tooltips, the preview dimming while stale, the answer coming back after the divide-by-zero egg, a taken number in numbers and a thread's scroll to its newest line no longer fade or glide. Motion that is the point stays: connect 4's drop, game physics and the egg effects themselves.

**Hover labels (native only):** AppKit's tooltips (`.help`) are replaced in the bar, threads, graph and game shell by `.hoverTip` (`Bar/HoverTip.swift`): the word tip's ink pill, solid and with a shadow, under what's hovered after 0.6 s, gone the moment the pointer leaves. The word names use the same 0.6 s, and once any label has shown, the next shows at once for 5 s after the last was on screen (`HoverTip.wait`). The edge tools' tips wait 1.5 s every time. Settings and the other shared windows keep AppKit's.

**Typed angle units (native only):** a quotient before a unit in a trig argument is one angle in either mode, `cos(π/4 rad)` (core `group_angle_quotients`); the web engine still reads the `π` form as blank.

**Angle marks (native only):** a faint `°` (degrees) or ` rad` (radians) after each sin/cos/tan/sec/csc/cot argument that doesn't say its own unit (core `angle_marks`): `50sin(26.87)` shows `50sin(26.87°)`. A mark hides while the caret is in its argument (being typed, it would sit where the caret does) and shows once the caret leaves; one inside the line sits in a gap opened after the argument, one for an argument still open after the text with the grey `)`.

**Solved letter shown (native only):** a solve with one root reads `D = 26` in the answer slot (the page shows `26`), as several roots already read `x = −2, 2`; an exact-and-decimal one reads `x = √2 ≈ 1.41421`, and a solved row in the tape shows its letter too. Clicking the number copies (or inserts) the number alone, the shortest text that reads back as it (`0.1`, not `0.1000…01`), and `ans` is the number.
